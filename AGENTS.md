# Repository Guidelines

## Project Overview

AuxFlow is a Python compiler and static analyzer for multi-pass LaTeX builds. It checks references and citations, classifies convergence, and plans engine runs before typesetting. `auxflow run` executes the plan and checks the resulting auxiliary files.

## Architecture & Data Flow

- `src/auxflow/cli.py` owns the command surface and the shared analysis pipeline. The console entry point is `auxflow.cli:main`.
- Source passes through `lexer` → `parser` → `ast` forest → `semantic` tables and diagnostics → `ir` auxiliary reference graph (ARG).
- `analysis` propagates taint, finds strongly connected components, estimates stable passes, and classifies results as `CERTIFIED`, `BENIGN_CYCLIC`, `AMPLIFYING`, or `UNKNOWN`.
- `planner` lowers the classification to a versioned `BuildPlan`. `runtime` runs TeX tools and compares normalized auxiliary state across passes.
- Keep the compiler core independent of `runtime` and TeX. Only `runtime` may start subprocesses. `analysis` consumes the ARG, not the AST. Put needed information into the IR instead.
- Preserve safety: a non-certified plan cannot have fewer than three engine runs. Reject `AMPLIFYING` unless the caller uses `--force`. Unsupported constructs become opaque facts and reduce certainty.

## Key Directories

- `src/auxflow/{lexer,parser,ast,semantic,ir,analysis,planner,runtime}/`: compiler stages and execution.
- `tests/{unit,golden,property,e2e}/`: phase tests, deliberate snapshots, invariants, and a corpus classification guard.
- `docs/reference/`: current architecture and phase specifications. `docs/project/` and `docs/evaluation/` contain project and evaluation material.
- `examples/quickstart/`: small LaTeX inputs for CLI checks. `bench/`: corpus, harness, baseline scripts, and published results.
- `scripts/`: optional figure, screenshot, and review-document generation. These scripts are not part of the normal compiler workflow.

## Development Commands

```bash
source .venv/bin/activate  # if using the local virtual environment
make install          # editable install with development dependencies
make test-fast        # exclude engine and slow tests
make test             # full pytest suite
make lint             # ruff check src tests bench/plan
make format-check     # check formatting without edits
make type             # strict mypy on src/auxflow
make plan-validate    # deterministic implementation-plan check
auxflow check examples/quickstart/simple.tex
auxflow classify examples/quickstart/simple.tex
auxflow plan --explain examples/quickstart/simple.tex
```

`make format` writes changes. `make bench` only prints a notice. Use `bench/README.md` for benchmark commands. Use `python -m build` to build a release artifact after installing the build tool.

## Code Conventions & Common Patterns

- Use four-space Python indentation, a 100-character Ruff line limit, type annotations, and strict mypy. Follow `pyproject.toml` and `.editorconfig`.
- Represent tokens, spans, AST nodes, facts, plan steps, and results with typed dataclasses. Keep source spans on nodes and facts. Give every ARG edge and plan step a reason.
- Use `Diagnostic` values with source spans for malformed input. Preserve parser recovery. Model unsupported constructs as opaque facts. Use assertions for internal invariants.
- Keep analysis synchronous and explicit. Mutable builders and symbol tables assemble facts, then later stages consume their outputs. There is no dependency-injection framework or async pipeline.
- Add parser command signatures in `parser/signatures.py`. Keep CLI options, summaries, and examples consistent in `cli.py`. Avoid a third-party graph dependency: SCC and dataflow algorithms are implemented in this repository.
- State the assumptions behind analysis claims. Do not claim a model-minimal pass count is globally minimal. See `CONTRIBUTING.md` for research and claim rules.

## Important Files

- `pyproject.toml`: package metadata, console entry point, optional dependencies, and tool settings.
- `Makefile`: development commands. `.github/workflows/ci.yml`: CI checks on Python 3.12 and 3.13.
- `src/auxflow/cli.py`: CLI and shared pipeline. `src/auxflow/ir/graph.py`: ARG lowering. `src/auxflow/analysis/classify.py`: result states.
- `src/auxflow/planner/lower.py`: build-plan policy. `src/auxflow/runtime/execute.py`: engine execution. `src/auxflow/runtime/normalize.py`: auxiliary-state comparison.
- `src/auxflow/runtime/update.py`: explicit PyPI update checks, local cache notices, and package upgrades. Only the explicit `update` command installs packages.
- `docs/reference/architecture.md`: layer boundaries. `docs/reference/ir.md` and `docs/reference/build-planner.md`: data and planning contracts.
- `docs/changelog.md`: documentation changelog. `src/auxflow/_version.py` is generated by hatch-vcs. Do not edit or commit it.

## Runtime/Tooling Preferences

Use Python 3.12 or newer and pip for editable installs. The core has no third-party runtime dependencies. Hatchling and hatch-vcs build the package and derive its version from Git tags. CI tests Python 3.12 and 3.13. Use Ruff, mypy, pytest, and Hypothesis from the `dev` extra. Jekyll builds the separate `docs/` site.

## Testing & QA

- Add isolated unit tests for changed compiler phases. Use pytest fixtures such as `tmp_path` and `monkeypatch`. Run a focused `pytest tests/unit/test_<phase>_<topic>.py` before the full suite.
- Keep `tests/property/test_safety_invariant.py` strict. Non-certified plans must retain the conservative run count. `tests/property/test_lexer_roundtrip.py` checks token coverage.
- Change `tests/golden/fixtures/` snapshots only after deliberate review. Do not regenerate them automatically.
- Use fake TeX executables on `PATH` for routine runtime tests. Mark tests that require a real engine with `engine`. Mark costly tests with `slow`. `make test-fast` and CI exclude both markers.
- No coverage percentage is configured. `tests/README.md` expects unit coverage for each phase and corpus-level classification checks. `tests/e2e/` currently guards the table-of-contents corpus case.
